## 1. 已实现的案件契约

`CaseBundle`将以下内容分开：

| 区域 | 结构与默认规则 |
|---|---|
| basic_info | 法院、案号、事故日期、车辆型号；缺失value为null；有原文也只是未确认候选，多个候选标ambiguous，不自动选定 |
| documents | 每份原始文件、文件名、SHA256、解析文本快照SHA256、解析版本、正文单元与解析报告 |
| evidence | case_id、document_id、原文件与文本快照哈希、解析版本、页/段/表格位置、字符区间及原样引文 |
| facts | documented_fact（材料记载，未确认）或confirmed_fact（用户明确登记人工确认）；不混为一类 |
| claims | 当事人主张；不自动提升为事实；说话人不确定则保留null |
| inferences | AI/模拟分析中的推断及原文依据；支持关系始终待人工核验 |
| unclassified | 不确定类别的原文摘录，同时产生人工分类任务 |
| timeline | 引用独立事件证据和同事件时间证据；保留日期/分钟/秒/未知精度及原修复约束 |
| pending_items | 信息缺失、解析缺口、推断复核、未分类事项；缺失value保持null，有检查文档范围，不假造原文 |
| reviews | 人工真实性确认的复核人、依据、范围和北京时间记录 |

案件标签由操作者命名，不冒充正式案名。只有`confirm_fact`才能把材料记载升级为人工确认，且必须有引文、复核人、依据；明显主张/不确定表述不能仅换个类别就确认。程序不能验证复核人身份和实际核实行为，所以“已确认”明确是用户录入的结论，不是AI或系统证明真实。模拟材料也继续标明非真实案件。

规则、AI和模拟结果均不会自动进入已确认事实。模拟结果的origin标为simulation，来源模式保留“非AI调用”；来源模式不明不冒充真实AI调用。重复导入保留人工确认和审查记录。

## 2. 案件与文件边界

- 文档由用户明确加入指定案件，不按相同文件名、法院或案号自动合并案件。
- 同名但内容不同的文件有不同ID，不覆盖原件；相同文件重复归档幂等。
- 证据ID包含案件作用域，传入其他案件的证据ID会拒绝；同一文件确需用于两个案件时必须分别明确归档，两案证据/事件ID仍不同。
- 添加引文时核验原字节SHA256、解析文本快照、字符区间和quote；不以文件名或“S001”作为全局来源证明。
- 导入现有分析时重新构造模型契约并执行`validate_analysis`，再比对服务端重新计算的事件/时间锚点；篡改日期、偏移、来源、版本或换文件不能借“已校验”字样导入。
- 所有分析绑定校验先完成，再归档陈述和时间线；回归测试确认错误分析不会部分写入案件。
- 原始字节仅在当前Streamlit会话内存保留，不写入仓库、默认磁盘或模型输入。可以按当前案件下载原文件；案件JSON包含文本和来源清单，不内嵌二进制原文件。

缺失内容没有可引用的正文时，不伪造引文。解析失败通过原文件哈希、报告覆盖项、位置和错误代码定位；待核实事项记录它针对哪些文档，不能将未读区域写成事实。

## 3. 解析报告

新增`parse_document`返回文本单元及报告；兼容接口`core.read_units`仍返回单元列表，致命失败抛出的`DocumentParseError`携带同一报告。`core.extract`增加original_bytes、parser_version和parse_report，其余字段和原Excel格式保留。

报告含文件哈希、解析版本、状态、逐项覆盖清单、问题代码/中文说明、计数、限制及是否需要人工确认。没有宣称“全文100%覆盖率”。

### PDF

- 逐页提取；单页异常保留空占位和`read_failed`报告，其他可读页继续处理，物理页序不乱。
- 无内容流/图像/注释的页面标结构空白；有图像却无文字的页面标疑似扫描；只有图形或无法判断时标no_text，不武断认定空白或扫描。
- 发现图像、疑似乱码、资源检查失败时提示人工检查；不解码图片做OCR。
- 检查PDF结构树中的Table标签；**不保证检测所有视觉表格**。无标签也始终标明表格内容/单元格完整性未核验，不能将文字抽取成功等同于表格已全部读取。
- 图片计数仅检查XObject资源，内联图像和复杂图形不能保证识别；PDF阅读顺序、版面坐标和视觉表格仍需对照原件。

因此普通文本PDF也可能显示partial，原因是表格/版面完整性仍未核验，不是宣称其文字提取全部失败。

### DOCX

- 读取正文段落、普通表格和嵌套表格，嵌套位置保留父表/行/列路径。
- 按XML物理单元格检查，不因合并单元格重复计算同一格文本。
- 比较检测到和处理的表格、物理单元格、段落数；内容控件内未读表格、单元格读取失败等产生覆盖缺口。
- 对文本框、图片/绘图、修订、内容控件、域、嵌入对象及页眉页脚/注释等未支持区域明确列出，而非把这些内容编入正文。
- XML路径、段落/表格位置和正文单元索引用于定位；不冒充Word页码或完全还原视觉版面。

### 错误及版本

损坏、加密、不支持类型、20MB文件上限、PDF超过300页、DOCX解压80MB/5000个条目上限均有结构化失败/拒绝报告。页面和单元格内部异常只显示通用原因，不把异常中的原文或内部详情呈现到页面。

解析契约升级为`core.read_units/v2-coverage`。模型Schema保持2.0，固定模拟响应更新解析版本；原模拟DOCX字节不变。旧解析记录提示重新读取，旧结果不能自动标成新版本。原事件—时间绑定、未知时间、精度和跨文件快照校验保持。

未来修改解析算法或输出不同的依赖升级仍须更新解析版本。该契约名不是完整环境锁定证明。

## 4. 页面验收（无需API密钥）

1. 在本分支独立本地副本安装requirements，按照README设置仅本机演示的`APP_MODE="local"`，运行`python -m streamlit run app.py`。默认公开模式无访问密码仍锁定。
2. 加载原6份模拟样本，验证原关键词检索、人工核验和Excel导出。
3. 选择PDF和DOCX，在“解析覆盖检查与报告”查看逐页/逐单元格信息并下载JSON；空文字样本不应生成虚构内容。
4. 在“案件结构化工作区”创建操作者案件标签。此时文档为空，不自动归档此前上传的所有文件。
5. 明确选择文件加入本案；原件、解析报告和证据分别保留。也可点“加入模拟事故材料及离线分析”，该操作只导入明确标识的本地固定样本，不调用模型。
6. 查看材料记载、主张、推断、时间线、待核实事项和证据索引。默认没有人工确认事实；相反主张并存。
7. 在本案选择原文位置和唯一连续摘录，保存类别；重复出现无法唯一定位时要求扩大/更换引文，不自动选第一处。基本信息同样只能保存原文值。
8. 添加缺失信息时注明检查文件，value应为null；无法读取不表示现实不存在。
9. 人工确认材料记载需另行核实真实性并填写依据和确认框，不只是核对文字。程序仅记录用户的复核结论。
10. 切换新案件，不应自动带入其他案件的文件或事实。下载案件JSON及对应原件；清空会话或退出登录后不再显示这些案件。

解析报告有未覆盖/未核验区域时，现有发送确认框会明确追加“已查看解析报告、仅分析已读范围”，保留既有确认流程。后端也要求coverage_acknowledged；未确认在扣额度/创建SDK客户端前拒绝。解析失败永远不能靠勾选继续分析。这是既有AI功能的保护，不是本轮付费调用。

## 7. 仍存在的问题

- 没有OCR、PDF视觉表格结构还原或可靠的全版面遗漏检测；“疑似扫描”是结构线索，不是扫描类型鉴定。DOCX未支持的区域仍需人工查看，物理XML计数不是语义完整性证明。
- 没有原始EDR/CAN解码、证据采集合法性判断、完整保管链或材料真实性验证。哈希证明一致性，不证明来源可靠。
- 事实/主张/推断的语义准确性仍需人工审查。人工确认是用户登记结论，不能单凭密码登录视为专业人员身份认证。
- 不自动跨文件校时或判断因果；重复导入幂等，但没有完整的多运行版本合并、历史对比和撤回审查工作流。不能用后续分析自动覆盖人工确认。
- 原件和案件只在当前会话内存保留；刷新重连/服务重启可能丢失。JSON不嵌原件，也未提供JSON重新导入恢复功能；请另外下载/保管原文件。
- 未增加解析进程CPU/内存隔离、可终止总超时和累计会话大小预算；单文件/页数/解压限制不能替代这些保护。公开多租户和外部统一限流仍未实现，当前仅适合受控演示。
- 没有真实API或浏览器视觉验收。测试通过表示这些有限自动化场景通过，不代表生产安全、所有文件都能完整读取或法律结论正确。
- 新案件JSON含解析正文、引文及复核人信息，应作为用户主动导出的案件材料保管，不提交到公开代码仓库。源代码下载白名单不包括运行时上传文件。
