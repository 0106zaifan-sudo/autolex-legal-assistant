# AutoLEX V2.0-D：跨文档证据冲突审查与人工复核增强

基线：`feature/v2c-case-workspace-roundtrip` / `1df304f49b226cf1549a9d1e31280a660c3b7c26`。开始前基线工作区干净，另建worktree与独立分支 `feature/v2d-evidence-conflict-review`。基线完整505项实际复跑通过（49.224秒）。不修改main、planning或验收分支，不部署，不读取/修改Secrets，不调用真实模型，不使用真实案件材料。

## 功能与操作

1. 在已有案件中归档材料、保存不同原件的连续引用。已有关系可直接审查；没有关系时，明确点击原有“发现本案证据关系候选”或新工作台的“发现已保存锚点的关系候选（离线）”。两者均复用CaseStore.discover_relations，不调用模型。
2. 打开“证据冲突审查工作台”，按时间记载、提示命题、信息缺口或最新人工状态筛选。筛选只影响显示，不删除候选或审阅记录。
3. 选择审查对，查看原自动候选/规则依据、当前只读解释、两侧完整引文和上下文、文件名/文档ID/证据ID/位置/字符范围、文件与解析快照及引文SHA256、时间文本/精度、命题环节与核验限制。
4. 查看最新复核与历史，选择人工关系类型/状态，填写复核人及理由，点击“追加本次审查记录”。只能追加RelationReview，不覆盖EvidenceRelation，不调用confirm_fact，不修改原件或时间线。
5. 使用V2.0-C工作包保存；清空会话后导入，同版本规则下重新计算审查视图，原候选与审阅链保持一致。筛选状态和未提交表单是会话草稿，不进入工作包；清空资料也清理这些草稿。

完整引文和上下文采用禁用编辑的文本框，保留原值（包括末尾换行），可滚动阅读；没有按关键词裁剪主体、否定或限定语。原材料下载、原有关系视图、AI分析及工作包功能继续保留。

## 只读架构与兼容性

`conflict_review.py` 提供 `review_pair(store,cid,left_id,right_id)` 和 `build_workbench(store,cid)`，输出 `conflict-review/1` 版本化解释，不写回CaseBundle。

- 先复制当前案件，构造“文档/证据/关系/关系审阅/历史回执”的审查子图，复用workspace_bundle.validate_graph核验来源、自动关系规则、AI原建议/回执及审阅链。故意不重放无关事实或真实性确认，连已有truth_confirmation也不会触发confirm_fact。
- 每一侧再次使用原verify_span核验原件/解析快照/版本、原文位置与quote，检查文档归属、解析报告来源及不同文档字节的独立性。非法引用、跨案污染、坏哈希/坐标、旧解析版本等直接抛出安全错误，不生成有效结论，不自动修复。
- 完整证据显示不变；解释可在严格中性元信息边界内识别主体/事件ID/时间。事件ID位于引文之前时，必须将其单独定位到同一原始单元并调用make_span生成只读上下文锚点；不会凭文件名、相同文字或同一关键词关联。
- 原自动候选、当前规则解释、最新人工意见分别展示。新的四环节解释可能比旧规则更细，但不覆写旧候选method/type/reason；人工修正仅追加已有RelationReview。
- CaseBundle继续1.1/1.2，V2.0-C工作包仍为autolex-workspace/1.0，无迁移、无新增持久字段。解释由已验证案件重算；未来解释版本更新可能改变只读建议，但不会重写历史候选/审阅。

本轮保持evidence_relations.py、relation_ui.py、case_store.py、case_schema.py、evidence.py、workspace_bundle.py、原AI/候选选择/SDK/权限/额度模块不变。

## 时间差的两层语义

必须区分**原文时间文本的字面算术**与**真实时刻的可靠比较**。固定材料没有认证时区或时钟基准，因此不能证明真实间隔或先后。08:30与08:31的展示如下：

```json
{
  "literal_delta_seconds": 60,
  "reliable_comparison": false,
  "actual_delta_seconds": null,
  "selected_time": null
}
```

`literal_delta_seconds`按右侧显示值减左侧显示值；界面展示绝对量“1分钟（60秒字面差）”，同时醒目标注真实时刻不可可靠比较。不选择哪个正确，不校准时钟，不补时区、不推断先后或因果。日期精度仅产生literal_delta_days，不补午夜或伪造秒数。

允许字面算术的条件：

- 同一可定位的显式候选事件编号。相同编号仅支持候选事件关联，不证明现实事件同一性。
- 只接受完整闭集碰撞记录语法：可有“现场记录：/摘要：”前缀，唯一完整公历日期及受旧解析器支持的时间，后接“车辆发生碰撞”。可保留明确独立的“原始日志未提供。”尾句，不将其他事件时间拼入。
- 同一时间精度；缺日期、多重时间、精度不同、不同/缺少事件ID、上下文未证明独立、时间不确定、不支持语法或显式时区/时钟疑问均不计算差值。即使出现明确UTC/北京时间等，本版也不处理时区换算。
- 原文单元必须已读取。通常要求parsed且无覆盖风险；两份固定PDF实际为partial，仅因统一的pdf_table_coverage_unverified警告，而对应页为read。该特定通用警告允许对已验证文本做字面算术，仍显示partial和警告，不声称表格完整或文本内容真实。其他读取失败、修订/未覆盖问题会阻断时间、强命题及缺口解释。

没有时区信息并不建立共同真实时钟；字面算术只是显示文本的数字关系。若材料明确写有时区/时钟疑问，或后置语句限定“上述/该记录/时钟/事故时间…”，即使当前锚点截去了这些内容，也保守阻断。无法可靠比较的真实时刻字段始终为空。

## 四环节命题规则

闭集支持以下八个完整表述，可带明确“企业说明/企业主张/驾驶人陈述/驾驶人主张：”前缀，原前缀仍完整显示：

| 环节 | 明确肯定 | 明确否定 |
| --- | --- | --- |
| 系统发出 | 系统已发出接管提示 | 系统未发出接管提示 |
| 车辆输出 | 车辆已输出接管提示 | 车辆未输出接管提示 |
| 驾驶人接收 | 驾驶人已收到接管提示 | 驾驶人未收到接管提示 |
| 驾驶人感知 | 驾驶人已感知接管提示 | 驾驶人未感知接管提示 |

同候选事件、同字面主体/对象/环节的肯定与否定可生成“不一致候选”；一致文字仅为“支持候选”。字面“系统/驾驶人”相同不认证现实实体或同一时段，检查建议明确要求再核对。

不同环节为一般关联，**系统发出与驾驶人收到不是同一命题，不能机械认定矛盾**。命名主体、同义改写、引语、转述、反问、如果/可能、并非未/未必没有等复杂否定、多命题混合和不明确归属均不推测，返回待核实。普通“提示”也不自动等同于“接管提示”。

完整引用不等于语义完整：引文前存在非中性主体/主张说明，前一解析单元存在实质文本，或后续有承接限定时，采用保守范围判断，不截前缀洗成客观事实。只跳过完整匹配的已知虚构声明及事件编号元信息。牺牲召回以避免制造冲突。

## 信息缺口与检查建议

只识别当前证据记录行中独立、完整的“原始日志未提供”表述，另生成准确只读锚点。不能从下一条事件记录借缺口，也不能把“否认原始日志未提供”“未提供？”、引语或主张截成客观缺失。上下文或解析覆盖不满足时不生成缺口解释。

建议只包括有材料依据的检查对象：核对时区/时钟/精度/原始记录，分别核查提示发出/输出/接收/感知，或检查是否另有原始日志。所有建议明确是检查建议，不假定EDR/DSSAD等材料存在，不认定现实中不存在日志，不判断责任、证据真实性或法律意义上的矛盾。

## 人工复核与保护

复用CaseStore.review_relation / RelationReview。modified、rejected、needs_review、confirmed均只是关系审阅状态；confirmed不升级事实。原自动候选保持不变，review_id / previous_review_id / reviewer / reason / reviewed_at完整追加，切换审查对会重置草稿，避免上一项目理由误用。

提交前再次验证审查子图，不仅依赖按钮或旧预览。任何失败只显示固定错误代码，不回显未验证原文。工作包恢复按原V2.0-C全图规则再次验证，新功能不绕过原子导入、身份门禁、预算、限流、超时或人工核验。导入历史仍不等于身份认证。

解释层当前最多300条关系、每个完整原文单元最多24000字符；超限明确拒绝，不截断引文或静默丢弃关系。原有界面与原件仍可查看，需人工缩小审查范围；本版不新增数据库或大规模聚合推理。

## 剩余风险

不是通用语义理解：有限闭集、严格上下文规则可能漏报或返回大量待核实；不把无提示视为无风险。事件编号、字面角色、不同文件字节均不能证明现实事件/实体/材料独立性；时钟与真实性由人工核验。新只读解释可能比旧自动候选更保守，必须结合两侧全文与原候选审阅。

工作包的签名/加密/身份认证及解析资源隔离限制沿用V2.0-C，没有以本轮功能解决。算法版本升级后解释可能变化，旧候选与人工历史仍保留；若需要永久保存“当时的解释快照/规则版本”应另行设计明确Schema与迁移，本轮不静默扩展。
