## 既有规则逐项核对

`ai_analysis.SENTENCE_END = [。！？!?；;\r\n]`。

`_timeline_binding()` 先检查单一主引用、事件正文与 event_source.quote 完全相等，再做以下检查：

1. `item.text.rstrip('。！？!?；; \t')` 仅在用于检测的临时变量中移除尾部标点、空格与Tab，存储引文和坐标不变。剩余正文中存在 SENTENCE_END 即 timeline_multi_sentence。
2. 所以中英文分号和中英文感叹号/问号、中文句号在内部均拒绝；末尾这些标点可以保留。CR/LF即使在末尾也没有被rstrip去除，仍拒绝。逗号、冒号不是该规则的句界，英文点号也不在该正则内；不能因此把逗号、冒号当安全截句位置。
3. 紧邻原文的前后边界还必须为已有分隔符或单元边界，不能截掉时间、主张前缀、否定或限定词。检查失败为 timeline_incomplete_sentence。
4. 主引文内的时间必须唯一、完整且与 time_text/precision 一致，time_source 必须等于 event_source；未知时间继续使用 unknown/unknown/未知/null。不能借其他句段或其他文件的时间。
5. `build_sources()` 按行保留换行分块。跨行拼接通常在 quote_not_found 阶段已经拒绝；带尾部换行的合法来源引用仍可能在时间线绑定层拒绝。本轮分别测试两层，不能混淆错误阶段。

原Prompt“完整单句”没有列出分号/换行边界、末尾换行、语义依赖和不安全拆分策略，表达没有完全对齐本地规则。这是明确可复现的协议指导缺口。未发现需要放宽安全规则的证据，本轮不修改 ai_analysis.py、SENTENCE_END 或 _timeline_binding。

## 最小修复

仅替换 multidoc_ai.PROMPT 的一段时间线指导，明确：

- 每条事件使用一处连续、独立、完整的原文句段，text=event_source.quote，sources仅含该引用。
- 不含内部句段分隔符，不跨行，末尾换行也不包含；允许原样保留句段末尾标点。
- 保留陈述主体、否定词、限定语、主张前缀和完整时间信息；不得为过检截掉时间或结论上下文。
- 如果分号前的主张/否定支配后句，不独立摘后句冒充事实。不能安全拆分时保留有来源的事实/主张，并提出有来源待核查问题，不强造timeline事件。
- 不自动拼接、删内部标点、合并行、改写原文、补事件或借其他日期。

没有在程序中自动剪引文或制造事件，也不修改现有输出。Schema、prompt_version维持兼容；现有 prompt_sha256 记录实际Prompt变更，并改变 batch_sha256，避免复用旧批次同意。

## 剩余风险及下一次真实验收

Prompt不能保证模型每次遵循；本轮没有自动改写兜底，不合规则仍拒绝。现有分句器是字符边界规则，不是语义证明：分号两侧可能仍有主体/否定依赖，嵌入引用、简称或特殊标点也可能造成保守拒绝，必须人工复核。为避免语义截断，Prompt允许保守不输出不安全事件，时间线因此可能不完整；已有完整性诊断也不是完整性保证。不能把所有facts复制为timeline来补齐。

下一次经人工审查并明确授权后，仅对原四份虚构材料做一次真实联合分析，检查：服务商是否正常、facts.reasoning仍为空、timeline是否使用独立完整引文、不含尾部换行、08:30/08:31分别保留、未知时间事件不漏、主体与否定/主张不变，以及待核查问题没有无源新增。核对安全回执的Prompt哈希和三层验证状态；若失败，下载validation_diagnostic定位，不自动重试。

本轮真实API调用0次，不读改Secrets，不部署、不合并。离线通过只证明已构造反例及合法引文的本地行为，不证明第三次失败的具体标点，也不证明下次真实模型完整性或语义正确性。
