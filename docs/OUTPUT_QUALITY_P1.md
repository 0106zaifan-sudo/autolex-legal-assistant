# P1输出质量：分类、去重与表达

日期：2026-11-09（北京时间）。基线：`feature/multi-provider-deepseek`的`9ea9fd1`；独立分支：`feature/output-quality-p1`。开始时原工作区干净，使用新worktree开发，未修改基线分支或覆盖用户工作。用户已告知基线通过SIM_A/SIM_B真实DeepSeek自动验收及人工复核；本轮不读取这些真实记录，也不重新执行付费验收。

## 问题与修改前后

回归材料均为原SIM_A/SIM_B和内存构造的明确虚构材料。模拟响应是人工构造的反例，不是用户真实模型输出或新的模型效果评测。

| 问题 | 修改前行为 | 本轮行为 |
|---|---|---|
| facts混入推断 | Schema及原validator允许kind=推断，因而直接进入事实/主张展示区 | 全量证据校验通过后，保持kind、text、reasoning、来源不变，移入待核实列表；有可审计记录 |
| facts和pending重复 | 同一待核实事项在两处显示 | 移动后仅在类型、正文、问题及完整证据锚点全相同时合并；原条目保留在审计字段 |
| 同处重复条目 | 完全相同的facts或pending条目重复展示 | 同列表亦只合并完全重复项；保留顺序及原始条目审计，不改写内容 |
| “是否完整是否尚未核实” | 只检查问题前缀和问号，可通过并展示 | Prompt要求具体核查问题；小范围规则发现已覆盖的重复疑问短语时明确output_quality_failed，不自动改写、不作为有效结果 |
| 模拟声明当案件事实 | 完整模拟声明可被当作事实或未知时间事件 | 两种已知完整中性声明移到document_metadata；保留原文、位置及文件SHA256，原文件仍完整保留 |
| 版本难以区分 | 只有绑定契约版本和具体Prompt哈希 | 保留Schema/绑定Prompt版本，另记prompt_revision和output_quality_version，均为output-quality-p1/v1；继续记录具体Prompt哈希 |

Prompt同时明确：facts只放客观材料记载与有原文归属的主张；推断应在争议/待核实列表，不把文件元信息当案件内容；同一锚点的同一问题不重复；问题须具体、可核查，不能添加原文未涉及的设备、人物行为、时间、金额、证据已存在/缺失或时间同步结论。

## 处理顺序与证据约束

实际SDK路径依次执行：访问/解析覆盖检查 → 原额度预留及SDK调用 → 原Schema校验 → **完整原证据校验** → 输出质量检查/整理 → 返回分析。质量整理不能把失败引文或错误时间变成有效结果。

`validate_analysis`、`_fact_classification_diagnostic`、CLAIM_MARKERS、所有SHA256/source定位及时间线绑定/排序函数均与基线相同。主张不能直接当事实的保护继续执行；伪造source_id、错误时间及被篡改坐标即使出现在待合并条目或元信息里，也先拒绝。案件导入仍重新校验所有展示条目，不信任质量版本标签。

只有已经通过原校验的结构化结果进入`_apply_output_quality`。整理保留所有原文与问题字符串，不进行语义改写，也不将推断改成事实或主张。

### 精确去重范围

去重身份由kind、text、reasoning和完整来源元组组成：文档SHA256、解析文本SHA256、解析版本、source_id、unit_index、start、end、quote。不能因同一句文字出现在不同位置或来源就视为重复。

已有pending条目优先保留其顺序，再补入facts中误放的推断。不同问题即使共用引文也不合并；相反主张分别保留；合法事实/主张与基于同一引文的不同研究问题也保留。正常timeline与issues不做自动合并。不会通过跨文件合并来“去重”。

推断从facts移入pending属于保守的未决事项归类，不会自动判断其是否为已成立的法律争议。Prompt优先要求模型正确分类，仍需人工区分具体问题用途。

如果移动后pending超过原Schema允许的8项，明确返回`output_quality_failed / pending_capacity_exceeded`；不截断问题，也不输出无法按原案件导入契约重验的结果。原始输入不会被改变。

### 问题质量规则

仅检查reasoning，识别“是否是否”和“是否完整/齐全/缺失/缺漏是否”这一小类明确重复模式。原文text/quote即使包含病句也保持不变；不修改材料以改善表达。

“是否需要核实原始日志是否完整？”和用逗号区分的不同问题不会被一概拒绝。规则不是自然语言或法律语义证明，未覆盖的别扭表达仍可能通过。语义支持关系仍待人工核验，不报准确率。

质量错误回执保留provider/model/usage及原预算信息，标记`evidence_validation_status=passed`、`validation_error_kind=output_quality`并给出固定规则及安全定位；不记录问题正文，不自动重试，失败占用额度与输入预算。原私有捕获仍只针对证据绑定失败，本轮没有扩大保存原始模型输出的范围。

### 元信息与审计

只自动识别以下两种完整独立中性声明，且条目必须逐字等于完整声明、所有引用都属于只含该声明的原文unit：

- `【模拟数据：完全虚构，仅用于AutoLex模型集成验收，不是真实案件】`
- `【模拟数据：AI事故分析测试材料，纯虚构，不是真实案件】`

不是“出现模拟字样就删除”。真实事项中提及“模拟数据声明”等文字不会被隐藏；其他未知元信息只通过Prompt引导，不做宽泛删除。

返回JSON增加`document_metadata`和`quality_audit`。每次移位/合并记录规则、原section/下标、目标section/下标及完整original_item，包括来源。`counts_before/after`说明各列表变化，质量版本说明整理策略。重复条目的原内容仍可审阅；审计事件数不等于净删除条目数（一次条目可能同时移位和合并）。

这些字段只属于已生成分析JSON，不内嵌到模型原始Schema，也不用于证明材料真实。审计包含原文，敏感性与分析JSON相同，不打印到公开日志、不提交仓库。原文件及会话中的材料标识保持不变。当前案件导入只导入重新校验的sections；需要保留整理过程时同时保存原分析JSON，案件JSON本身不新增审计存储模块。

## 剩余风险与最小真实复测

本轮没有新模型效果结论。精确去重不会合并同义改写、部分重叠引文或不同reasoning，避免错误合并；这些可能仍显重复。已知声明之外的元信息依赖模型遵循Prompt，自动识别覆盖有限。确定性问题检查只覆盖少数重复短语，不能证明其他问题自然、具体或有充分语义支持。超容量或病句会明确拒绝整个新分析，可能增加下一次用户自行复核/重试的工作量，不自动消费更多API次数。

用户另行授权后，建议使用现有受控CLI：先单独SIM_B一次，检查facts无推断、S006主要在pending且不重复、reasoning自然且不新增事实、声明不作事实、碰撞时间仍未知、来源可回放；再单独SIM_A一次，核对相反主张、事故/维修日期、精确重复整理及全部引用。最多两次预先授权的正常分析，不自动重复失败请求；继续使用原认证、预算与限流。

同时检查回执中的prompt_revision、prompt_sha256、output_quality_version和人工质量结论。旧的真实验收通过不自动等于新Prompt已通过；离线247项通过也不能当作模型准确率或新真实验收通过。
