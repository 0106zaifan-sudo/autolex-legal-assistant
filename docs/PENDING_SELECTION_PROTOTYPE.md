# Pending evidence编号选择：独立离线原型

基线：feature/b01-supported-data-term-fix / 6998b6f968ee839a17a3df4d978dc3891e99080c。分支feature/b01-pending-evidence-selection-prototype，独立worktree。

## 实施前架构评估

三次真实回执均格式通过、证据失败。两次text_not_in_quote只能证明text未在本条quote集合中连续存在；unsupported_data_term只能证明EDR/DSSAD在当前引用集合缺少字面支持，不能认定问题本身虚假。没有真实原始响应，不猜测具体text、quote、reasoning。31779 tokens为用户报告的第三次用量，不是本轮调用或可独立核验的计费明细。

| 字段 | 生成责任 | 约束 |
| --- | --- | --- |
| 候选编号、case/document ID、原件/解析哈希、解析器版本、位置、原文、原文哈希 | 程序从当前归档生成 | 完整原文、准确坐标；不同来源不同编号 |
| 主证据anchor_id、全部evidence_ids、reasoning | 模型语义选择 | 显式选主证据及每个来源，不能让程序补找替换 |
| kind=推断、text、sources、核验状态 | 程序确定性恢复 | text=主证据原文；保留全部选中来源；待人工核验 |
| 问题是否有价值、主体归属、跨文档关系、证明力 | 模型建议及人工复核 | 引用校验通过不保证语义蕴涵，不确认事实或责任 |

| 方案 | 优点 | 代价/风险 |
| --- | --- | --- |
| 原自由摘录 | 引文细粒度灵活，旧协议无需变化 | 模型复制/拼接text、quote会失配，反复改Prompt无确定性保证 |
| 预验证编号选择（本轮） | 原文恢复确定，来源显式，保留多源，复用旧验证器 | 仍会选错、漏选；完整句段较长；语义问题仍在 |
| 让模型只返回字符坐标 | 避免复制原文 | 模型数坐标易错，依旧要确定边界和上下文 |
| 仅用source_id整块引用 | 简单、保留当前来源 | 长行切块可能丢前缀，边界/版本/主证据责任不清；需要可信候选封装 |
| 相似搜索后补换错误引用 | 表面提高成功数 | 改变模型证据选择、可能修成另一命题；禁止 |
| 引用模板+规则生成全部问题 | 可预测 | 覆盖范围窄且易隐藏漏项；不能替代语义分析 |

采用独立pending-evidence-selection/1.0-prototype，不替换multidoc-analysis/1.0或1.1。只在离线入口运行，不提供真实SDK调用或生产导入。CaseBundle、ZIP、已有Prompt及其指纹不变，不静默迁移旧数据。模型对象禁止自由text、quote、文件名、坐标、kind和确认状态字段。

候选使用当前来源块中的完整物理行（含原始换行、分号、主体及否定词），不按分号拆成独立事实。原解析器把超长行切块时，原型排除该整行的片段并报告，不截取成独立证据。前文归属仍需上下文核查，完整行不证明语义独立。上下文标题可明确选择为附加来源，不能只靠文件名或隐式补入。候选不等于事实、真实证据或技术功能认定。

候选清单、模型选择、当前档案必须一致；请求前后重建清单核对，所有引用再走现有validate_case_output/check_inference。超出规模、重复/未知编号、主证据未选中、错案/错快照或任何一条验证失败均整批拒绝，不自动修复、重试、截断或导入。

## 实现及操作

新增模块`prototypes/pending_evidence_selection.py`，与现有网页/模型入口隔离：

1. `prepare_selection`复用prepare_case检查同案2—4文档、原件和快照。对完整物理行调用make_span预核验，生成PE编号、位置、三类哈希及清单哈希。编号绑定案件/文档/来源/位置，不能跨案件借用同文文本。
2. 准备只读的独立Schema及离线输入；编号枚举限制为当前清单，模型只能选择anchor_id/evidence_ids与reasoning。外层case_id、batch_sha256、catalog_sha256由程序给定，返回值必须严格相同，不承担语义判断；复制错这些上下文仍会拒绝。
3. `validate_selection`根据当前档案重建准备结果，拒绝被修改/过期的目录、坐标、哈希。主证据必须明确属于选中集合，不自动添加；重复引用/重复事项拒绝，独立问题保留。
4. 程序逐字恢复主证据text和每个已选sources.quote，包括完整换行、分号、主张前缀及否定词。随后调用原validate_case_output/check_inference，技术术语、时间、法律引用、推断标识和存在性保护照旧。
5. 任意条失败整批抛出安全错误，不返回部分有效结果、不修改CaseStore。成功也只返回独立原型产物，标记provider_status=not_called、semantic_status=pending_human_review、production_import_allowed=false，没有SDK、额度或导入入口。

原型不复用事件候选目录本身，因为待核实事项也需要日志缺口、来源限制及标题，不能限于独立事件。复用的是“调用前验证+稳定编号+确定恢复+调用后重验”模式。完整物理行比细句粗，可能含上下文不足；候选不保证独立命题或真实性。超过1000字符而被原解析器切块的行不成为可选片段，excluded明确报告，无静默裁剪。

安装既有requirements依赖后，从项目根目录执行：

```bash
python tools/run_pending_selection_prototype.py --output /tmp/AutoLEX_pending_selection_demo.json
python -m unittest discover -s tests -p test_pending_selection_prototype.py -v
python -m unittest discover -s tests -v
```

此命令无--run-live、无付费确认或密钥参数，只读取固定D01/D03/D04；人工按完整原文唯一匹配构造演示编号，不是运行时相似搜索修复模型引用。准备结果保留解析风险确认清单，但离线不请求授权；未来真实请求必须重新取得授权并沿用原QuotaStore/预算/超时，不能把原型视为调用入口。

演示[JSON](PENDING_SELECTION_DEMO.json)包括三组合法人工选择、无术语来源/未知编号反例，以及“企业主张被误称驾驶人自述”的语义反例。所有数据明确为虚构，不能作为实际DeepSeek输出或通过率。

## 三类问题分别结论

| 类别 | 本原型结论 | 验证边界 |
| --- | --- | --- |
| text改写/拼接、quote复制错误 | 在清单和选择通过校验时，由确定性恢复消除自由复制字段造成的失配 | 非法额外text/quote字段直接拒绝；未知ID/错误上下文仍可能格式或选择失败 |
| 选错、漏选、选中不相关证据、标题遗漏 | 不能消除 | 未知/跨案ID、未选主证据拒绝；合法但不相关编号可能通过绑定；不补找或删除来源 |
| EDR/DSSAD等无引用依据 | 原保护保留，失败可继续发生 | 只有显式选择标题或实际含术语正文才提供字面支持；选择正确标题不证明技术功能 |
| 主体误归属、跨文件概念转移、因果/责任过度推断 | 无法靠编号校验自动解决 | 专门反例在字面绑定通过后仍是待人工核验，不开放生产导入或确认事实 |

三次失败类别均有人工反例：旧自由协议D01+D04、D01+D03概括text依旧触发text_not_in_quote；编号选择恢复对应连续原文后可通过；D04只选不含EDR的正文仍unsupported_data_term，显式选标题后通过。不能将这些反例说成本次真实响应的重现。

完整行恢复保留主体/否定及标点，但并不保证跨行继承的主体范围。文字相同的不同文档、同一文档不同位置保留不同编号和坐标，不按文字去重。原型保留最多4来源，超过即拒绝；不因容量不足抛弃关键来源。不同问题对同一组证据可以并存。

## 兼容策略与风险

生产multidoc-analysis/1.0、1.1、单文档Schema2.0、CaseBundle1.1/1.2及V2C工作包编解码完全未改，旧Prompt及批次指纹也未变。现有工作包/历史分析回归继续通过；另有原型前后ZIP恢复及原型不能作为已验证analysis附件混入ZIP的测试。

这是**隔离而非静默迁移**：原型不产生可导入的生产分析/调用回执，不把prototype产物当成1.1结果，也不升级历史记录。将来若进入生产，需单独定义例如multidoc-analysis/1.2，保存新选择原稿、目录版本和哈希、恢复审计及新回执；扩展ZIP附件校验时要版本分派，保留1.0/1.1读取路径，不放宽旧规则。未完成这些适配前不得把新格式提交到当前付费入口。

引用绑定不能证明问题有依据。旧检查仍有词面必要条件与语义蕴涵的差距：合法编号可以被误选；EDR/DSSAD在任一选中quote出现不等于其可用于其他文档；时间字面出现不等于该时刻适用于问题；主体错误、提示发出/收到/感知混淆与隐含责任推断不一定被检出。原型明确保留这些反例和人工核验，不宣称提升模型语义准确率。

若超过4来源、超过长度或上下文不能安全保留，当前策略是拒绝/报告，不自动造句或删除来源。整行较长会增加输出恢复展示长度；目录和枚举元数据也有输入成本。少复制原文只是减少一种出错面，不承诺Token或费用一定下降，更不能解释用户报告的31779 tokens构成。
