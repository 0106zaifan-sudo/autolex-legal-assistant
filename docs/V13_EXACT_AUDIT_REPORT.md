```bash

  --receipt '/path/AutoLex_联合验证回执(8).json' \
```

## 短整数与短非连续字母数字别名的比较（仅建议）

目前真实编号尚未精确核定，以下只是设计取舍，不据此断言本次是复制错字，也不确定最终应采用哪种方案。两者都必须是**本批可信目录的传输别名**，服务端继续保留原PE/文档/快照/位置/原文哈希身份。

| 维度 | 批次内短整数（标准B01例如0—61） | 短非连续ASCII别名（示意K7MQ、R4XT） |
| --- | --- | --- |
| 复制负担 | 最短；需明确零基并严格整数 | 比整数多几个字符，仍远短于27字符PE；可排除0/O、1/I等混淆 |
| 抄写错误检出 | 20写成21仍在密集有效集合，通常检不出 | 稀疏集合中的错字更可能不在目录；这是可测试倾向，不是模型准确率保证 |
| 进一步检错设计 | 仅范围/enum不能识别相邻有效误选 | 可在生成阶段约束批内编码距离或校验位来提高单字符错误检测；只检测，不对输出做近似纠正 |
| 合法但错源 | 高风险：数值合法仍可能引用另一主体/文档 | 同样存在：选了另一个有效别名仍会通过绑定 |
| 易混机制 | 一基/零基、负数索引、bool等于0/1、浮点/字符串强转、跨批复用 | 大小写、混淆字符、补全成常见词、旧批次别名复用 |
| 所需强约束 | StrictInt、实际enum、上下文/映射SHA、明确重授权、禁止换算 | 严格ASCII精确匹配、定长/实际enum、相同上下文与映射SHA、禁止大小写/近似修复 |

如果后续评估重点是“抄错必须尽可能暴露”，可优先对短非连续别名做离线原型，短整数作为复制负担最低的对照。不能因短整数更容易输出就优先牺牲检错能力。别名应避免EDR1等带来源类别暗示的名称，不能诱导模型根据名称而非原文选证据；如无法在上限内生成完整互异编码，应拒绝，不裁剪目录。

两种方案都要固定排序与映射版本；先对index/alias到完整证据身份的映射计算摘要，再把该摘要绑定批次指纹，避免循环依赖。请求前捕获、请求后重建核对，只用该请求的可信映射恢复。不能按全局序号或另一个案件的别名查证据，不能让模型回传映射哈希来代替程序核验。ZIP保存原始选择、映射摘要及恢复锚点并按明确新协议分派，旧1.3冻结。

无论选哪种表示，仍须完整并排原文、全部独立来源、主体/否定/时间限定与人工驳回。合法编号不是语义正确，不能自动确认事实或责任。需要先依据真实目录完成本轮核对，再设计新协议；本轮不实施1.4或任何生产改动。
