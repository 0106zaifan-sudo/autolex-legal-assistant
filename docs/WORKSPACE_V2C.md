# AutoLEX V2.0-C：案件工作包与离线恢复

开发基线 `feature/v2b-event-candidate-selection` / `a1920b55c59262685bd8b8705c3bf53daa0afa1e`。基线工作区干净，独立worktree及分支 `feature/v2c-case-workspace-roundtrip`；基线456项离线测试实际复跑通过（35.781秒）。本轮不改main/planning/原验收分支，不部署，不调用真实模型，不读改Secrets，不接触真实案件或私有验收记录。

## 使用流程

保存：在案件工作区选择案件，展开“下载案件工作包”。有当前案件的联合分析缓存或恢复后仍保留的历史分析附件时，可以明确勾选纳入；没有缓存时禁用，不假装能重建模型原始输出。点击“生成案件工作包（校验后下载）”，重解析和验证通过才出现“下载案件工作包”。案件或勾选附件发生变化后旧下载缓存失效，必须重新生成。文件名 `AutoLEX_案件工作包.zip`。

恢复：即使工作区没有案件，也可打开“案件工作包导入工具”。选择ZIP、确认恢复历史的含义，再点击“导入案件工作包”。成功后切换至恢复的case_id，可查看/下载原始PDF/DOCX、证据坐标、事实/主张/推断、时间线、关系候选和完整审阅历史，以及案件级历史安全回执。整个流程不创建新的AI调用、授权、人工确认或责任结论。

联合分析附件仅在用户显式选择时保存。恢复后置于独立历史附件区，显示来源、可查看或下载，不放回 `_md_result` 或单文档AI调用缓存、不自动将附件中尚未归档的条目写入案件；可以再次显式勾选后保存到新工作包。保存和恢复均重放原分析验证与导入校验，但副本中新增的记录全部丢弃。

原“下载本案结构化JSON”继续保留，仍不内嵌原件字节。新功能不引入数据库、后台备份或自动云同步。会话关闭后，只有用户已经下载到本地的工作包可以用于下一次恢复；请妥善保存。清空本会话资料同时清除工作包、上传控件、历史附件和下载缓存。

## ZIP与版本

```text
manifest.json
case.json
files/<document_id>.pdf 或 .docx
analysis.json                     # 仅明确勾选并重新验证通过时存在
```

`manifest.format_version=autolex-workspace/1.0`，记录case_id、parser_version、原件document_id→路径、analysis_included，以及每个非manifest成员的路径、实际字节数和SHA256。case.json保持当前CaseBundle 1.1/1.2结构；DocumentSnapshot.original_bytes仍不内嵌JSON，而从files成员恢复。当前解析器 `core.read_units/v2-coverage` 必须完全匹配；不静默迁移未知版本、旧解析或不一致快照。

不遍历服务器目录，不序列化Streamlit session_state。ZIP只接受上述精确布局；API凭据、Secrets、配额SQLite、登录状态、调用同意、私有debug目录和任意附加文件没有入口。案件和分析JSON的结构、回执字段有白名单，拒绝授权/凭据键和可识别的密钥/私钥字符串模式。原始材料可能包含业务隐私，工作包本身未加密；自动检测不可能识别所有自由文本密码，应在本地保管，分享前人工检查。项目源码下载ZIP仅加入新代码/测试/说明，不包含任何运行工作包。

## 资源限制与ZIP安全

| 检查 | 本版限制/策略 |
| --- | --- |
| 上传ZIP总字节 | 32 MiB；该控件单独设置32 MiB，不放宽全局PDF/DOCX 20 MiB上传限制 |
| ZIP解压后总量 | 64 MiB，按声明预检并逐成员核对实际大小/CRC |
| 成员数量 | 外层最多128项；每案最多16份原件 |
| 每成员/原件 | 不超过20 MiB；JSON最多8 MiB，manifest最多256 KiB |
| 压缩比 | 每成员解压字节/压缩字节不超过200 |
| 压缩方式 | 只接受stored/deflate |
| 路径/布局 | 不落地解压；仍拒绝绝对路径、反斜线、盘符、空路径段、`.`/`..`、控制字符、重复/大小写冲突和非白名单文件 |
| 特殊封装 | 拒绝加密、链接/特殊文件、外层目录、附加注释、自解压前缀/尾随数据、分卷和不一致local/central标志；坏ZIP/CRC拒绝 |
| DOCX内部ZIP | 同样预检路径、数量（最多2000项）、64 MiB解压总量、20 MiB单项和压缩比；允许正常内部目录，不提取到磁盘；拒绝宏/ActiveX/嵌入对象及危险脚本成员、XML DTD/ENTITY（包括带空字节的UTF16表示） |

解析失败/rejected原件、本版无法精确重现的解析结果不打包或恢复；不会悄悄丢弃该文件。parsed/partial及可重现的空白/扫描材料可作为原件/覆盖报告保留，但不增加文字或OCR；未覆盖风险仍可见，未来AI请求需重新逐份确认。

## 验证与原子提交

1. 在大小边界内读ZIP，先检查成员清单、路径/属性/压缩限额，核对manifest结构、布局及每个成员的SHA256和实际大小；拒绝重复JSON键、非有限数、过深JSON及未知字段。
2. 依据case.json与原件清单逐份从原始字节调用现有CaseStore.attach_document重解析；检查document_id、文件SHA、parser_version、解析文本快照SHA、units、parse_report、规则候选和数据类型完全一致。比较规范JSON避免bool与整数相等造成松散匹配。数据不匹配直接拒绝，不改原件或坐标。
3. 在临时CaseStore中装载严格CaseBundle；所有证据使用原make_span/verify_span重新计算ID、文件/解析哈希、坐标、位置和连续quote，不信任JSON中的“已核验”。
4. 重放Statement身份与摘录/说话人规则；材料记载、主张、推断与待分类集合必须匹配，禁止改变核验状态。AI/模拟事实与推断再走原validate_analysis及输出质量检查。人工确认需对应原事实及唯一历史review，按原confirm_fact限制在验证副本中核查，不把新时间戳或确认写回恢复案件。
5. 每个CaseEvent按主引文重新执行原时间线绑定，核对source_event_id/event_id、statement/evidence引用、规范时间、时间精度、未知字段与时间证据坐标。不借其他事件日期；08:30与08:31分别保留。chronology_status只允许原有保守状态，不将排序认定为现实因果。
6. 核对基本信息摘录、待核实事项的文档/证据/推断/时间/覆盖报告引用。跨文档关系核查材料独立性、ID及原离线规则；AI原建议核查两侧独立锚点、重叠摘录、历史receipt文档范围，并再走原联合推断/语义约束，不将历史Prompt授权替换为当前授权。
7. 核查人工review归属、唯一性、时间格式、关系review链、上一记录和时间顺序；检查回执文档快照/案件归属、验证状态、token类型和费用记录的一致性；1.1历史回执的候选版本、清单哈希及选择ID重新匹配当前原件构建的清单，AI原建议与其run_id回执元信息也必须一致。只保留为历史，不认证服务商实际调用或复核人身份。
8. 可选联合分析在副本中重新执行现有import_case_analysis（含1.1候选选择重放），全部通过后丢弃副本上的新增条目。附件不自动改变案件结构。
9. 最后在短时进程内锁内重新检查case_id冲突，再一次性加入当前session CaseStore。任何前序失败都不改变现有案件；并发/重复导入同ID只允许一次成功，不覆盖，不自动重命名或重写证据ID。

恢复后主页面显著标记“导入历史未经身份或服务商认证”，不新增HumanReview/RelationReview，不提升主张为事实，不调用confirm_fact修改实际恢复对象。重解析和规则重放仅在临时验证对象进行，最终恢复的案件JSON与原导出保持一致。

## 历史“JSON＋四份原件”

提供独立受限入口：仅接受CaseBundle 1.1/1.2、当前parser_version、唯一且安全的原始文件名、完整且无多余文件的PDF/DOCX集合。文件名仅用来建立候选映射，之后仍检查全部文件SHA256、原document_id、解析快照、原文引用和审阅图，不能凭同名文件就接受。

缺一份文件、重名材料、内容变化、未知CaseBundle版本（包括未显式支持的1.0）、解析器/快照不一致均拒绝，不能通过补空数据、自动降级、重写位置来迁移。历史JSON没有会话级原联合分析缓存时不会凭空恢复；已经存于案件的事实/时间线/关系/审阅与回执可在核验后恢复。未知版本需另行研究明确迁移方案，或用原件新建案件人工重新归档，不静默兼容。

## 剩余限制

- 工作包没有数字签名或身份认证。能发现内容与引用不一致、断链及不允许的确认，但攻击者若完整重写一份内部自洽的包，哈希不能证明其历史真实。不能宣称识别所有伪造review或认证“真实模型已调用”。这是离线便携历史，恢复保留状态且标注来源，不是重新真实性认定。
- 工作包未加密，含原件、可能的个人信息及审阅人姓名；丢失/泄露需使用者自行管理。本版不提供密码ZIP、密钥管理或云端备份。
- 严格的解析器/快照一致性和DOCX封装安全限制可能拒绝某些合法旧数据；库升级、字体/PDF提取变化也可能使重解析不一致，需单独明确迁移，不能直接绕过。
- ZIP及DOCX解压有硬限额，PDF/DOCX解析仍使用当前应用库，不是完整的恶意文件执行隔离或CPU/内存沙箱。公开面对不可信大规模文件前需进一步研究隔离解析、资源期限和签名/加密方案；本轮不部署。
- 只恢复案件及显式附件，不恢复检索页全局records、会话认证、上传选择、模型调用同意、冷却/额度计数或私有调试目录。配额数据库保持现状，导入不减少也不新增AI调用记录。
- 所有模型响应来自本地Mock；本轮真实API调用0次。离线恢复通过不等于材料真实、法律结论成立或新的真实模型验收通过。
