## 4. 文件解析、检索与溯源的详细判断

### 4.1 解析可信度

当前系统保留的是解析后的文本位置。PDF物理页序不等于裁判文书页码，DOCX段号不等于Word页码；文本层抽取还可能乱序。原始文件SHA256能检验同一字节文件，不证明来源真实、采集合法或内容完整。

辅助驾驶初审需要另行记录：材料提供方、采集时间/方法、原始载体、脱敏情况、文件哈希、文档版本；对车载数据还要注明时区、时钟源/漂移、软件/OTA版本、功能状态、适用运行条件和日志完整性。现有系统没有这些字段。建议本周先支持“文档化的记录及人工录入元数据”，不要扩展成原始EDR解码或司法鉴定意见生成。

### 4.2 检索定位

`core.search`可保留为资料筛选器。它返回文件而非法律条款，有AND词约束而无相关性排序；同一案件的PDF和DOCX副本不能当两个独立案例用于评测。P1应另外建立受控法源索引，保存权威发布链接、版本、生效区间和条款锚点，按事故时点和争点检索，再形成初稿。

### 4.3 核验分层

建议拆为四层：摘录一致性（程序可验证）、材料真实性（人工/外部程序核实）、争议状态与陈述归属（待人工确认）、法源版本/效力/适用（单独核实）。当前“待人工核验/已人工核验”只记录用户结论，不能同时代表以上四层。

## 5. 模型集成条件与真实调用边界

AI分支已有真实官方SDK调用入口，并非只有演示JSON；但本次确认的是代码路径和mock结果，不是线上实际调用成功。

实际启用需要：安装规定版本；Streamlit Secrets的`OPENAI_API_KEY`；可用模型及API项目额度；`APP_PASSWORD_HASH`并完成登录；公开模式设置单实例并配可写持久SQLite；用户确认有权向OpenAI发送选定正文。固定官方endpoint、`store=False`、输出4000token、输入24000字符/80块、关闭自动重试均已落实。

本次没有读取生产密钥、检查API余额或调用真实模型。平台账号有ChatGPT订阅不能据此推定有API额度。`store=False`不代表第三方服务零保留，勾选发送确认也不等于已自动脱敏。

真实集成验收建议只发送明确标识的模拟事故材料，记录模型标识、prompt/schema版本、输入哈希、调用时间、真实usage和结构/引证校验结果；请求失败就如实记录失败。不得为证明“真实AI”向仓库上传密钥或未授权真实案件。
