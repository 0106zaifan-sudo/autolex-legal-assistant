# V2.0-B 时间线候选选择：结构性修复

基线 `feature/v2b-timeline-quote-fix` / `de85fcc236b52f51a33c0c54742a8699c387c9c5`。独立分支 `feature/v2b-event-candidate-selection`。基线工作区干净，另建worktree；不修改main和既有验收分支。

## 根因边界与方案

用户报告连续真实调用服务商完成、格式通过，但时间线引文两次触发timeline_multi_sentence、索引不同。旧契约仍要求模型自由重复事件正文、主引文、来源列表、时间来源，Prompt不能保证这些字段选择一致且恰好满足分号/换行边界。安全回执没有模型原文，本轮不能确定第四次失败由哪个具体字符引起，也不读取私有验收记录。

本轮改变生成契约：**调用前构造并校验连续句段；模型只选择候选编号和事实/主张类型；程序按原始候选恢复引用与时间，再运行全部原验证。** 不是把已被拒绝的模型引文剪裁成合法文本，也不修改或跳过原验证器。

## 三层结构与版本

1. `event-candidates/1` 清单：case_id、document_id、file_sha256、parsed_text_sha256、parser_version、批次全局source_id、unit_index、location、start/end、quote、quote_sha256、allowed_kinds、时间状态/精度/原文时间及CE_编号。编号哈希包含版本、来源身份、坐标、引文与时间等字段，相同文字不同文件/案件不会合并。
2. 新请求/响应 `multidoc-analysis/1.1`、`multidoc/candidates-v1`：facts、pending_evidence、relations保持原类型，timeline改为 `[{"candidate_id":"CE_<24位十六进制>","kind":"事实或主张"}]`。禁止额外字段，不允许模型提供quote、text、source或时间。请求Schema给出当前有效编号enum；无候选时timeline的maxItems=0。本地仍独立验证编号、归属、分类和重复，不依赖服务商服从enum。
3. 恢复后的内部结果仍通过原1.0多文档契约和单文档Schema2.0，CaseStore案件1.2不变。结果增加candidate_selection，包含清单版本/哈希及原始1.1结构化选择，用于重放审计；raw_output保留完整恢复的1.0原文结构以兼容现有验证与导入。不能把内部投影版本误认为本次真实请求版本，真实请求版本以receipt为准。

1.0的prepare/request/validate/analyze接口保留用于旧调用者和离线回放，不放宽旧规则。**网页新请求只调用analyze_case_candidates，1.1失败不自动回退1.0，也不接受1.0自由时间线响应。** 编程调用新功能必须明确使用analyze_case_candidates；原analyze_case是兼容入口，未悄悄改变其契约。单文档AI不变。

批次授权哈希绑定当前来源、两版Prompt哈希、候选算法版本和新Schema；调用回执另存candidate_catalog_sha256。请求后重建档案和清单，发现变化拒绝。任何算法/中性前缀规则改动应升级CANDIDATE_VERSION；现有已归档历史不自动迁移或重写，旧临时分析可能需要重新授权分析。

## 保守提取规则

- 逐解析单元、逐原始行扫描，按已有 `。！？!?；; CR LF` 句界提取连续范围。只在选择范围时排除边缘空格/换行，保留原文中已有终止标点；没有删除引文内部标点、合行或改写字符。
- 只跳过完全匹配的已知虚构材料声明和中性的 `事件编号：<字母数字连字符下划线>` 前缀。声明不是事件。未知前言不按“像元信息”猜测安全可删。
- 同一解析单元出现实质前文后，后续句段默认不再证明语义独立，记录context_dependency_not_proven而非生成候选。跨单元的主张、否定、引出语（如“以下/如下/…：”）继续保留依赖范围。这会漏掉本来独立的后续事件，是有意的初版保守取舍。
- 只为明确事件词范围提供候选；无事件词、重复引文无法唯一定位、跨source块、未知边界及旧绑定失败都不入候选。排除记录只列坐标和安全规则代码，原文件仍在案件中，没有删除材料。
- 保留完整主张前缀、否定和限定语。有主张/待核实标记或明确单方说话人的句段仅允许kind=主张；中性材料摘录允许事实或主张，最终仍通过原分类规则。候选通过只证明原文摘录一致，不证明内容真实；自动分类无法覆盖所有隐含语义。
- 唯一且受原时间解析器支持的完整时间从原句确定，date/minute/second不补精度。无时间、多时间、含不支持精度/不确定时间都保留unknown/unknown/未知/null，不借其他句段日期。
- 每个候选在发送前调用原validate_analysis，包括_timeline_binding和原分类规则。发送后的恢复结果再次执行原全部验证、质量处理、完整性诊断及关系语义策略。

对于语义不明确的段落，系统不自动升级事实，也不自动生成事件。模型仍可在facts/主张与有来源pending_evidence中保留相关事项。可选清单不覆盖全部重要事件；网页明确提示排除与人工核查遗漏。

## 完整链路与安全保护

1. 同案选择2—4份已归档材料，核验文件/解析快照和版本，逐份确认解析风险。
2. 构造候选、检查64项上限（不静默截断）；原材料仍受既有8000/16000字符和96来源块限制。
3. 新请求字符预算包含原材料文字与候选重复引用文字，合计上限16000；完整序列化请求（包括Schema enum、清单和元信息）计算字节预算，再加原1024字节余量。两种额度通过原QuotaStore reserve_ai一次预留，超限在调用前阻断。不重置/退款规避失败记录。
4. 网页列出全部材料、候选数量及排除风险，批次明确授权后一次调用。沿用服务商适配、官方SDK、认证、共享并发/冷却/总额度、超时及max_retries=0。
5. 1.1格式验证通过后重建当前来源与候选清单；按编号恢复原句、全局source和时间，拒绝未知/跨案编号、重复选择、不允许的kind。安全诊断记录candidate_selection阶段、timeline索引、必要source_id及固定格式candidate_id，不输出原句。
6. 恢复结果必须完整通过原引文/坐标/哈希、事实分类、时间绑定、问题质量及关系语义验证后才能预览。未通过抛错、保留usage和安全回执，不返回可导入结果。无自动重试或不安全降级。
7. 用户再次明确导入时，重建候选并重放原始1.1选择，比较审计哈希及全部恢复结果；缺审计、改编号/清单/引文均拒绝。原子导入沿用现有CaseStore副本机制；不确认真实性、不触发confirm_fact、不覆盖人工审阅。

安全回执和案件analysis_receipts保留新请求版本、候选版本/清单哈希和通过验证的选择ID；回执不含quote或完整模型输出。联合分析JSON本来就含敏感原文，新增candidate_selection同样只供当前案件明确下载/导入，不能当公开日志发布。AI关系原建议的Prompt来源取本次receipt，不冒记旧Prompt。

## 四份固定虚构材料与实际离线验证

现场08:30事故句、驾驶人未收到提示、企业说明系统已发出提示、摘要08:31事故句分别产生四个不同候选。终止句号保留；事件编号前缀不作为事件；两份事故记录分别保留，后两条提示事件没有日期，使用未知时间。摘要中后续“原始日志未提供。”未硬塞入事故句或制造时间线事件。这个合法清单是调用前程序构造的，不是本轮真实模型输出。

新增测试先在旧代码失败，再实现。核心测试使用人工选择响应与两服务商官方SDK+httpx.MockTransport，走真正的请求序列化、1.1解析、编号映射、原验证及显式导入；AppTest实际点击网页新入口并原子导入，所有模型返回均本地注入。测试覆盖同文本不同来源、跨案编号、完整坐标/哈希、作用域、时间差异/未知/精度、自由引文拒绝、重复选择、旧响应不降级、清单审计/恢复文本篡改、权限授权/额度/预算/部分解析、失败不污染、人工历史保留及安全导出。完整数量和日志见TEST_REPORT及v2b_event_candidates_tests.txt。

## 剩余风险与真实验收建议

本补丁将自由引文的不稳定性转为有限候选选择，可阻止模型生成跨句/跨行的时间线引文。但模型仍可能漏选、选错事件类型或生成不合规facts/推断/关系；未知编号或任何其他证据失败仍整批拒绝，不能承诺下一次一定通过。字符规则和有限上下文标记不能证明语义独立，嵌套引语、隐含说话人和跨文档真实性仍需人工核查。首实质句之后的保守排除、非事件词漏检、长句跨块和支持范围外时间会降低召回；没有OCR或自动时间推理。

动态enum和1.1结构已通过官方SDK本地HTTP Mock，尚未向DeepSeek/OpenAI服务端发送，服务端支持/遵循情况与Token变化仍未验证。候选重复文字增加输入开销，现有预算可能提前阻断原来能发送的大批次，这是显式安全取舍。

人工代码审查通过后，最小真实验收仍用原四份固定虚构材料，一次明确授权联合调用：确认发送1.1、catalog版本/哈希可追踪；恢复四条原文引用、08:30/08:31独立、两条未知时间；事实reasoning为空，主张不升级、发出与收到不当矛盾；待核查与完整性没有明显遗漏。下载安全回执查看三层状态，失败只报告首个诊断，不自动重试。不要把本轮Mock通过称为真实验收通过。

本轮不调用真实模型、不读改Secrets、不读取私有验收/真实案件文件、不部署、不合并main。
