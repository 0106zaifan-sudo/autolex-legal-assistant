## 修复前后

审查探针A的原构造：碰撞原文包含11月1日08:30，另条维修原文包含11月2日09:00，模型将碰撞正文配到维修日期。旧校验只检查正文和时间分别命中任一引文，可通过。

现在每条时间线：

1. 有一个`event_source`，`sources`只能包含这条主引文，`text`必须完全等于它。
2. 句段必须唯一定位，不能跨句拼接，也不能从完整句段内截掉说话人、否定或限定成分。坐标由服务端计算。
3. 明确时间的`time_source`在模型响应中必须指向同一事件引文；不能指向维修或其他材料。程序在已校验的事件内计算精确时间子区间并导出时间锚点。
4. 事件引文必须只有一个可支持的完整日期/时刻，模型必须原样选择该完整表达；多日期、多时刻、估计或相对时间不能任选一个。无明确关系时应为未知，具体绑定失败则整份结果拒绝，不自动修补为看似成功。
5. 每项来源携带文档SHA256、解析文本快照SHA256、解析契约版本、source ID、页/段位置及字符区间。当前来源清单重新构建核对，不能用其他文件或旧文本快照的来源表。
6. 事件ID从文档、文本快照、解析契约和原文位置计算；同一锚点重复输出拒绝，矛盾主张保持两条，不擅自取舍。

## 时间状态与精度

| 状态 | 行为 |
|---|---|
| explicit + date | normalized_time只含YYYY-MM-DD；sort_time为空，不造已知午夜 |
| explicit + minute | 保留到分钟，不补成已知秒 |
| explicit + second | 仅在原文确有秒时保留到秒 |
| unknown | time_text为“未知”，time_precision为unknown，time_source及normalized_time为null，sort_time为空 |

支持完整公历中文日期、YYYY-MM-DD、YYYY/MM/DD，可选冒号时分/秒。不对纯时刻、相对日期、近似时间、时区、毫秒或未支持的中文时刻做推算或降精度；保留原文并使用未知/人工核验路径。

排序只在允许的精度内进行：按已知日期分组；同日出现date精度时保留原文位置顺序并标记日内顺序未确定；同分钟含minute精度时不认定秒级先后。未知时间在末尾按原文位置保留，不据此推断实际发生在其他事件之后。前后顺序不代表因果。

## 剩余问题与适用边界

1. 这证明的是结构绑定、字面引证及可回放定位，不证明材料真实性或全部自然语言语义支持。含多个动作但仅一个时间的复杂句仍可能需要人工解释；标点/换行是保守边界，不是句法分析器，PDF换行和转述上下文还需P0-B/C进一步处理。
2. 法律争议焦点和待核实证据的自由推断仍需人工核验，本补丁显式标`support_status`为“推断支持关系待人工核验”；未宣称修复审查B的全部语义问题。主张关键词分类的漏判/误拒也仍在后续范围。
3. 为避免跨事件挪日期，本补丁不自动跨段推断时间；复杂格式、跨页事件、长句跨1000字符块可能被拒绝或需标未知。80块/24000字符上限、OCR及解析覆盖缺口未扩展。
4. 解析版本为显式契约标识，未来修改核心解析或升级有输出差异的依赖时必须更新版本，不能把这个常量当成已记录完整解析环境。
5. 尚未实现案件级多文档关联、长期证据库、法律知识库、完整语义评测或真实模型效果验收；现有单实例部署边界不因本补丁改变。
6. 没有真实付费API调用或浏览器视觉验收；严格新契约对真实模型的成功率和输出token占用尚未测量。4000输出token上限保持，输出不完整时继续拒绝保存。
